# Task: search API with FastAPI (`src/api/`)

## Goal
Expose the pipeline through a small read-only HTTP API: full-text search over the `decisions` index, decision details, pipeline runs and quality results, with the interactive documentation generated by FastAPI on `/docs`.

## Two phases
1. **Contract proposal**: write `docs/tasks/search-api-contract.md` (routes, parameters, response schemas with examples, error cases) and **stop**. I review and decide before any code is written.
2. **Implementation**, once I have validated the contract.

## Constraints
- Search must reuse **exactly** the queries of `src/search/query.py`, with `DEFAULT_TITLE_BOOST` (2.0): this is the evaluated query. Filters and pagination are added around it, never by rewriting it.
- Search goes through the `decisions` alias only.
- Decision details are read from `silver.decisions` (PostgreSQL), not from the index.
- Judilibre decisions have no title: the API builds a display title in the legal citation format, e.g. `Cour de cassation, 16 septembre 2026, n° 26-83.146`, computed in the API, never stored.
- Read-only: no route writes to PostgreSQL or Elasticsearch.
- Configuration from `DATABASE_URL` and `ELASTICSEARCH_URL` (see `.env.example`).
- Never modify `src/search/mapping.json`, `src/quality/checks.yml`, or the "En bref" and "Avancement" sections of the README.

## Routes to cover in the contract
- search: text, filters (source, decision type, date range, sector), pagination, total hits, highlighted excerpts;
- decision details by source and identifier;
- latest pipeline runs (from `bronze.collection_runs`);
- latest quality results (from `quality.check_results`);
- health of PostgreSQL and Elasticsearch.

## Errors to cover in the contract
Decision not found, invalid parameter, Elasticsearch or PostgreSQL unavailable (the API must answer with a clear status, not crash).

## Tests (no Elasticsearch, no database, no network)
FastAPI's dependency overrides with fake search and database clients: every route, every error case, the Judilibre display title, and a test that the search route sends the same query as `query.py` (plus filters).
